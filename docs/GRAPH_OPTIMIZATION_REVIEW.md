The deployment goal remains the original VGGT at native 518 resolution on RK3588S. No replacement model, traditional pose frontend, omitted layer or omitted token is introduced. The real-time target is **not achieved**.

## Main computational target

In the saved native-resolution group0 profile, attention accounts for 52.23% of the operator-time sum. This is a diagnostic fraction, not a measured end-to-end speedup ceiling. The existing group already keeps normalization, QKV, RoPE, attention, residuals and MLP within a single NPU graph. Repeating a generic fusion or resident-buffer proposal would overlook that fact. Earlier split NPU/GPU attention improved one isolated component but slowed the complete original block. See the [group profile](../results/original_native518_memory_profile_v101.json) and [complete-block experiment](../results/original_native518_shared_block_v120.json).

Moving the four original 256-to-256 DPT `refinenet*.out_conv` 1x1 affines before their adjacent align-corners bilinear resize is a separate algebraic candidate. It reduces their symbolic MAC count by 4.328 GMAC per frame. Those four operations account for only about 17.4 ms per frame in the saved diagnostic profile, while the CPU resize operations remain. This is a bounded head experiment, not the main route to real-time poses.

## New candidate: remove the softmax-invariant key offset

This is a new candidate for this port, not a claim of a new attention method. The [SageAttention operator implementation](https://github.com/thu-ml/SageAttention/blob/main/sageattention/core.py) already uses sequence-mean key smoothing with INT8 Q/K and floating-point PV. Its CUDA/Triton kernels do not establish an RK3588 implementation or speedup; no package, checkpoint or alternative model is added here.

For each original attention head, after its original Q/K normalization and RoPE, define

```text
mu = mean(K over every original key)
K_centered = K - mu
scores_centered = Q @ K_centered.T
                = Q @ K.T - (Q @ mu.T) @ ones.T
```

The removed term is constant along each query row. Applying the original scale and key-axis softmax therefore yields the same probabilities in real arithmetic; the original V, output projection, residual and following layers remain unchanged. This candidate computes the global mean over all 2082 original keys across both frames, including special and patch tokens. Any one common center per head preserves the real-arithmetic identity; using a different center for each frame would change relative attention weights. The mean minimizes the sum of squared centered key values, but each key-channel range width and each score-row span remain unchanged. Q remains unchanged. Native storage padding is excluded from this mean and must not become an unmasked key.

The first [board FP32 screen](../results/original_native518_key_centering_v131.json) now passes on canonical A's complete frame0→global0 pair. Six Mean/Sub nodes cover both original B1 frame branches and all 2082 global keys; all 36 learned tensors and 79 original initializers remain unchanged, with a whole-parent inverse proof. On calibration pair0 [0,8], using its captured original NPU DINO24 input, frame/global relative L2 is 4.63e-8/6.87e-8 and both maximum errors are 1.43e-6. Both fixed gates and strict diagnostics pass; low-bit outputs are not byte-identical. Four saved endpoints and both CPU controls were independently checked. The two CPU calls validate this conditional graph representation, not NPU speed or quantized accuracy. Mean/Sub adds O(SD) work, and neither a smaller quantization grid nor an acceleration benefit is established.

Fresh board calibration now uses the same four predeclared inputs and the exact original SDK configuration. It takes 594.70 s with a 12,411 MiB calibration peak RSS; this is not deployment inference time or memory. All three K and QK activation quantization steps become coarser. Global QK changes from 0.26740 to 0.35074, approximately 31.17% coarser; its Softmax probability scale remains nearly unchanged. The saved catalogue uses asymmetric per-tensor activation quantization, so lower key energy does not imply a finer grid. This evidence does not support adopting mean centering. The SDK represents each mean using Transpose, Conv, Transpose and Expand, so selecting only the public mean output would not establish the intended arithmetic precision.

The bounded board compile resolves the placement question. It preserves canonical A's 20 highway/I/O requests and adds 18 actual Krope/mean/layout/Sub producer outputs. Independent operator and memory-table checks confirm all three complete centering chains use FLOAT16, followed by a conversion after Sub into INT8 Q/K/V buffers and INT8 SDPA on the NPU. The quantization-parameter section is byte-preserved. The 119 visible operators and 278 memory rows establish these boundaries, but do not reveal fused attention's internal accumulator or score precision.

The following normal diagnostic runs each model once on the same calibration pair0, in original-A20 then centered-A order, with flags0/core1 and the authorized 1 GHz controller. Both global endpoints remain nonfinite: original A20 has 114,745 NaNs and 1,225 negative infinities; centered A has 114,755 NaNs and 1,225 negative infinities. Their finite frame errors against the same original FP32 reference are 4.61865% and 4.61809% relative L2, and both fail the fixed gate. All four owned arrays were retained, the unchanged finite guard rejected the invalid results, the two contexts and four SDK buffers were released, and frequency/governor limits were restored. This centered runtime candidate is rejected. One ordered call per model establishes no steady-state timing benefit, and the missing Krope-FLOAT16-only control prevents attributing the tiny frame difference to centering alone.

Earlier descriptive statistics on three saved mixed-precision NPU key tensors removed 17.54%, 17.48% and 39.71% of their squared norms after centering. Each key-channel span was unchanged, and the first frame branch's overall range widened from approximately [-3.823, 2.795] to [-3.839, 3.277]. Those already rounded tensors came from a run with a nonfinite final global output. The fresh calibration above is stronger evidence and supersedes any inference of a quantization benefit from those energy statistics.

A post-RoPE per-head orthogonal Q/K rotation remains a separate hypothesis for smoothing operand ranges. It adds 272.9 million MAC to one 2082-key global block if implemented as dense rotations. It cannot be silently folded before position-dependent RoPE, and it cannot by itself improve the quantized score-output grid.

A separate zero-added-MAC candidate folds reciprocal Q/K channel balancing into the existing Q/K LayerNorm affine parameters. The actual 64-channel RoPE permits `D = diag(a, a, b, b)`, with 16 entries in each `a` and `b`: multiply Q gamma and beta by D, divide K gamma and beta by D, and leave LayerNorm statistics unchanged. This D commutes with every original positional rotation; shared norm parameters require the same scales across all 16 heads and all tokens of each block. The [board calibration screen](../results/original_native518_reciprocal_qk_v132.json) now used only four original saved calibration pairs and the predeclared nearest-power-of-two balance formula. All 32 frame and 32 global exponents were zero, so D is identity and no initializer changed. The eight saved FP32 endpoints are independently verified byte-identical to original A. NPU compilation is skipped for this identity outcome, without retuning the formula or drawing conclusions about nontrivial reciprocal balancing. Ideal score ranges remain unchanged, so this cannot by itself repair a coarse score-output quantizer.

## Precision-boundary gate

The [internal-softmax selector probe](../results/original_native518_softmax_precision_v131.json) reused the unchanged graph and calibration bytes, preserving 80 FLOAT16 requests and adding three genuine `q_softmax` requests. RKNN 2.3.2 accepted the 83-entry configuration and exported a model; its operator and memory tables match the old 80-entry compile, with all three fused SDPA operators and their Q/K/V buffers labelled FLOAT16. The existing policy already protected those attention operands and outputs, so this establishes configuration acceptance without isolating the added selectors. It neither demonstrates INT8 QK nor disproves independent internal precision control; score/accumulator precision and runtime numerical or speed effects remain unresolved.

A follow-up used canonical A's 20 highway/I/O requests plus three Softmax, three V-input and three PV-output FLOAT16 requests, leaving Q/K and `q_matmul` unselected. The actual compiler changed all three visible SDPA operators from INT8 to FLOAT16 and inserted six INT8-to-FLOAT16 Q/K conversions. Quantized upstream operands therefore feed floating buffers into the fused operator; this policy did not expose the intended INT8-dot/floating-score boundary. No runtime numerical or timing test was run. This outcome does not prove other mixed-precision policies or graph representations unsupported.

Four facts must remain separate: Q/K operand precision, dot-product accumulation, score-output requantization and probability/PV precision. A `float16` score selector might convert the whole QK operation to FP16. Conversely, an INT8 score output can retain a coarse quantization grid even when Q/K operand ranges improve. The independent [Rockchip MatMul API](https://raw.githubusercontent.com/airockchip/rknn-toolkit2/master/rknpu2/runtime/Linux/librknn_api/include/rknn_matmul_api.h) exposes an INT8-to-FP32 type, but that does not prove an equivalent boundary inside compiled fused attention or justify another costly external graph cut.

A changed graph needs matched board FP32 verification and its own calibration. Compiler acceptance and actual placement/precision evidence then determine which complete-block numerical and timing comparisons are worth running. Full replay, trajectory quality, fresh-pose latency, map cadence, sustained operation and physical 8 GB validation remain separate, unfinished acceptance steps.

## Moving a constant value component across attention

The [V-constant experiment](../results/original_native518_value_bias_fold_v133.json) crosses the original LayerNorm, attention and output projection. With row-vector storage, let `c = norm1.bias @ Wv + bv`. Replacing the V bias with `-norm1.bias @ Wv` and the projection bias with `bproj + c @ Wo` moves this constant outside the weighted sum. Each original Softmax row sums to one in real arithmetic, so `P(V-c) + c = PV`. The two complete blocks retain all 143 computation nodes, all tokens and every weight matrix; only four bias initializers are derived from the original constants. No runtime operator or dense product is removed.

Four predeclared real calibration inputs pass the board FP32 comparison at all eight endpoints. An independent saved-array audit finds maximum relative L2 `1.120121e-7` and maximum absolute error `1.907349e-6`; all eight strict elementwise diagnostics also pass. It independently reproduces the four derived biases and verifies unchanged node and other initializer bytes. This validates the conditional two-block FP32 rewrite, not full-model, quantized or trajectory accuracy. The intended benefit is reduced amplification of probability-row-mass rounding by the constant V component. Shared QKV quantizers and the derived projection bias may still worsen accuracy.

Fresh calibration of this two-output candidate is deferred while investigating the original A graph's frame-to-global boundary. The existing compiler shares the quantized public frame buffer with that internal connection despite the requested floating boundary.
