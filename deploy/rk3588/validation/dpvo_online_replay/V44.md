# v44 native-input recurrent replay

This research integration changes the input transport of the optional DPVO Update. It retains the frozen v43 metadata callback, nine-model catalogue, half-resolution policy, original 94 parameters, random sampling, D1 startup probe, complete-source grouping, output copies, BA and EOF. It does not change default VGGT or introduce ORB/LK/PnP tracking. The separate closed-flag cache experiment is not included in this replay.

`v44_online_factory.py` requires the completed v43 single/full-state transport prerequisites through the frozen full-AB harness. It replaces only an empty validated cache. Each new native context re-queries commands8/10 and checks the fixed NC1HWC2/C2=8 FP16 layout. Buffers are privately owned through synchronous output release; `pass_through=1` is not a zero-copy claim. Unsupported shapes and failed guards stop execution.

`run-v44-online-native-board.py` uses all frozen v43 CLI arguments, with the new factory/config and two extra required arguments:

```sh
--v43-online-driver /path/to/run-v43-online-npu-board.py \
--diagnostic-allow-native-fp16
```

The config retains all v43 fields and adds path/SHA pairs for `v43_factory`, `native_ab_harness`, `transport`, `packer`, `packing_library`, `query`, `packing_build_receipt`, `conversion_receipt`, and `full_ab_receipt`. The two diagnostic flags, motion probe and callback recorder are supplied by the driver. Board-local absolute paths in recorded receipts describe this execution and are not portable installation defaults. Compiled models, checkpoint, SDK library and image data are not redistributed.

The actual RK3588S run completes192 observations with158 fresh poses and12 separate EOF Updates. Active replay is54.094486seconds: **2.920815Hz**, fresh software admission-to-publication P95 **366.793772ms**, peak process RSS **515.507812MiB** on the16GB board. EOF takes another2.499685seconds and does not count as fresh. The process is serial and unpaced; physical capture and queued-frame age are not measured. Separate-run thermal histories do not establish a controlled speedup over v43.

The saved parity auditor reopens all eight NPZ pairs and compares55 raw array pairs, including14 final-state arrays, along with192 non-clock results and completed EOF. All match v43 bitwise. Initial/final RNG descriptors and digests match; raw RNG bytes were not separately saved. The trajectory evaluator uses the actual schemas, a fixed all192-source endpoint plan and common fresh observations. ATE/rotation RPE/translation RPE remain **0.019683m /1.793720degrees /0.036012m** on158 common observations and128 one-second pairs, still outside the10–20% target relative to full-resolution FAST.

The independent transport-record audit checks54 native attribute queries across all9 contexts,2895 pack descriptors and965 Update calls/releases. It also checks192 encoder calls and release/close declarations. Model files total66,123,629bytes; their `ctypes` host buffers total66,123,638bytes because each of9 buffers includes one terminating byte. Peak reported DMA is79,982,592bytes. These recorded counters and source checks do not replace raw output parity or whole-system RAM measurement.

Saved-audit attempts r1–r3 are preserved: the auditor initially looked for SDK pins at the run level instead of the context level, assumed SDK frame IDs were increasing call counters, and equated model file bytes with terminating-byte buffer capacity. The corrected r4 checks the actual frozen runtime contracts, exact SHA values and allocation bounds. The original completed board run was not modified or rerun to obtain this audit result.
