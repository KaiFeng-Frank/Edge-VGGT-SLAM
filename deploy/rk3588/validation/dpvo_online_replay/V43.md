# Metadata-only nine-shape online callback (v43 research)

This port changes only the successful full-Update `NPU_used` reporting query.
The byte-identical `npu_used_by_model` function from the tested v42 experiment
reads owned model-key/boolean pairs while holding the original cache/session
locks. It avoids copying the entire session history for this one query. Public
`metrics()` and `close()` still use the original complete lifecycle checks.
The helper does not infer SDK placement or accept any numerical result.

`v43_online_update.py` retains all v42 class methods except that reporting
block. The original owned input snapshot, finite/domain guards, full-group
execution/scatter, snapshot identity, unknown-shape failure artifacts, explicit
Torch D1 startup route, D3 EOF support, and failure/cleanup semantics remain.
No native transport, weights, RNG, preprocessing, graph, geometry, or thresholds
are changed. Historical SDK FP32 and half-resolution quality rejection remain;
the candidate is not adopted and default VGGT is unchanged.

## Scope of the source freeze

Fourteen generated/fake and AST checks passed. They verify the single reporting
change, complete D3/old-group output identity and ownership, stale/late/unknown
failures, explicit D1 routing, retained cleanup checks, unchanged factory
arguments, and the original frame loop/EOF/cleanup AST. Actual 192-observation
replay measurements and saved-data parity must be recorded separately by the
board owner. This freeze makes no speed, trajectory, all-NPU or 20 Hz claim.

Tests use adjacent sources by default. With repository tests outside this
directory, set `V43_ONLINE_SOURCE` to the source directory if needed and
`V43_PARENT_SDK` to the frozen sibling `dpvo_grouped_update` directory. No test
downloads dependencies or runs real models.

## Actual completed replay and saved-data checks

The recorded run completed the same 192 sensor observations and produced 158
fresh poses. Its [public evidence](../../../../results/dpvo_metadata_online_v43.json)
includes selected original run fields and the raw receipt hash, the independent
saved-array parity check and the separate JSON/GT trajectory evaluation. The parity auditor passed 389 checks:
all 192 nonclock observation results and all 55 raw array pairs from eight NPZ
pairs are bitwise equal to completed v42. This includes both before-termination
and final-state arrays and the three declared Update captures. Initial/final
RNG metadata and digests match; raw RNG bytes were not saved separately and
were not reread by this audit.

| Recorded boundary | v43 result |

| Fresh poses / planned observations | 158 / 192 |

The callback completed 181 full Updates and 34 explicit original-Torch startup
motion probes, with zero failed calls. EOF contributes no fresh observation or
pose publication. Cache close reports zero live contexts, model-host bytes and
DMA bytes; cleanup errors are empty. These counters do not establish all-NPU
operator placement. RKNN encoder and RKNN Update use the same board runtime,
with previously recorded internal CPU operations.

The shared fresh cohort contains 158 poses and 128 fixed one-second RPE endpoint
pairs. Its single positive-Sim3 evaluation produces ATE RMSE 0.019682977 m,
rotation RPE RMSE 1.79372034 degrees, and GT-scale translation RPE RMSE
0.036012289 m: exactly the same saved-pose metrics as completed v42. The
half-resolution quality rejection is retained. Against the original
full-resolution FAST DPVO cohort, these three errors remain respectively
76.92%, 81.98% and 110.76% higher. This is not an original-VGGT 518 precision
baseline, an adoption result, a physical-camera experiment, or 20 Hz/map/long
run acceptance. Separate v42/v43 replay timings are not a controlled speedup.
