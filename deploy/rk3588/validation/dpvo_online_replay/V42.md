# M16 EOF catalogue extension (v42 research)

This source adds only `B1_D3_M16` to the frozen v41 online catalogue. The six
v40 graphs and two v41 graphs retain their original manifests, compile/model
bytes and index entries. The factory delegates all eight existing validations
to the frozen v41 contract. This does not accept historical SDK FP32 errors or
the rejected half-resolution trajectory. The default VGGT path is unchanged.

`run-v42-online-npu-board.py` keeps the frozen v41 replay CLI and adds required
`--v41-online-driver PATH` to pin the original source (`73f5a4c...ea6d9`). Use
the new factory/config paths and SHA arguments. The schema changes to
`v42_cached_undistort_online_RKNN_research_replay`; the original per-frame loop,
termination call, geometry, RNG, correlation and cleanup AST stay unchanged.
No new execution options alter the trajectory. Its four tests are source/CLI
checks, and do not establish actual EOF, SDK or trajectory success.

`v42_online_factory.open_board_online_from_index(...)` keeps the v41 keyword
arguments and returns the same `OnlineM16Update` callable with `metrics()` and
idempotent `close()`. Add these explicit keyword arguments:

```python
old_online_compile_index=OLD_V41_INDEX,
old_online_compile_index_sha256=OLD_V41_INDEX_SHA,
v41_contracts=FROZEN_V41_CONTRACTS,
v41_contracts_sha256=FROZEN_V41_CONTRACTS_SHA,
v41_callback=FROZEN_V41_CALLBACK,
v41_callback_sha256=FROZEN_V41_CALLBACK_SHA,
eof_manifest=NEW_D3_MANIFEST,
eof_manifest_sha256=NEW_D3_MANIFEST_SHA,
eof_exporter=NEW_D3_EXPORTER,
eof_exporter_sha256=NEW_D3_EXPORTER_SHA,
eof_compiler=NEW_D3_COMPILER,
eof_compiler_sha256=NEW_D3_COMPILER_SHA,
```

The original `contracts` and `callback_path` arguments now select v42 sources;
`compile_index` selects the new nine-entry index. Keep the frozen v41, v40 M16
and v37 contracts adjacent to the new contract, with their original filenames
and bytes, because the frozen private SDK bridge reloads dependencies there.
The old callback only supplies its explicit source provenance pin; its code is
not executed by the v42 factory. The default context limit is nine.

The new index retains every old model entry verbatim and adds:

```json
{
  "schema": "v42_online_M16_Update_compile_index",
  "status": "staged_nine_online_shapes_diagnostic",
  "old_online_compile_index_sha256": "OLD_INDEX_SHA",
  "parent_manifest_sha256": "FROZEN_V39_M16_MANIFEST_SHA",
  "additions_manifest_sha256": "FROZEN_V41_ADDITIONS_SHA",
  "eof_manifest_sha256": "NEW_D3_MANIFEST_SHA",
  "candidate_accepted": false,
  "models": {
    "B1_D3_M16": {
      "compile_dir": "/absolute/new/D3/compile/directory",
      "compile_sha256": "NEW_COMPILE_SHA",
      "model": {"file": "block.rknn", "bytes": 1, "sha256": "NEW_MODEL_SHA"},
      "lineage": "v42"
    }
  }
}
```

This illustrative JSON omits the eight required unchanged entries; `bytes=1`
is a placeholder. Real receipts/model descriptors must be used. Validation
checks both old and new compile artifacts before any context initialization.

All complete source groups use RKNN, preserving each full target-by-16-patch
dependency and the original full-edge scatter order. `B2_D3_M16`, other unknown
shapes, padding, edge removal and silent Torch fallback are not supported. An
unknown shape saves full owned inputs and fails. Only the owner's explicit
`_neural(probe=True)` route calls the original Torch D1 startup probe; input
size cannot choose that route. Close the callback before parent SDK cleanup.

The D3 teacher is a new original-Torch forward on the saved v41 NPU-feedback
input. It is not the original CPU trajectory gold. Fixed `rtol=1e-4,
atol=1e-5`, finite/domain checks and historical rejection labels remain intact.
The source freeze records only tiny fake tests; real SDK, EOF, trajectory and
throughput validation is performed separately on the RK3588S by the board owner.

DPVO-derived geometry/grouping/execution logic is MIT-licensed, copyright
Princeton University (2022); see the byte-preserved adjacent `LICENSE`. No
checkpoint, compiled model, SDK library/header or dataset is included here.

## Actual RK3588S replay and saved-data review

The first v42 two-RKNN-stage run completed all 192 source observations and
158 fresh publications, followed by 12 offline EOF updates (24 BA steps).
Active replay took 58.554348 s (2.698348 fresh Hz); fresh software
admission-to-event-flush P95 was 386.036180 ms. EOF took a separate
2.970749 s. Peak process RSS was 510.852 MiB on the 16 GB board.
Nine Update contexts and one encoder context closed; reported context/model/DMA
counts returned to zero and cleanup errors were empty.

All 192 non-clock observation results and 41 saved-array pairs match the prior
v41 RKNN-encoder + RKNN-Update prefix. The failed parent omitted final RNG metadata, so only the
initial RNG is directly compared. Fresh trajectory metrics are unchanged:
common-population ATE/RPE still reject the full-resolution quality target.
This is not a controlled speed comparison, physical-camera latency, full-VGGT
accuracy, dense-map, endurance or 8 GB validation.

[Actual export, compile, replay and saved reviews](../../../../results/dpvo_eof_update_v42.json)
retain original full receipt hashes. The public replay record is an explicitly
selected field view, not the original run JSON bytes; source/input hashes and
saved audit counts remain visible. Raw models and feature arrays stay outside
the repository.

`run-v42-online-npu-board.py` keeps the v41 replay arguments and adds required
`--v41-online-driver` pointing to the frozen original driver. Select the new
factory with `--online-factory`, its actual SHA, and the
[nine-model board configuration](board-config-v42.json) with its actual SHA.
That configuration preserves the previous experiment paths and byte pins;
it is a reproduction record for the staged board, not bundled dependencies.
The actual half encoder, cached preprocessing, source images, policy, RNG,
correlation and BA are unchanged. Supply the explicit diagnostic flag.

For a new export, `export-v42-m16-eof-source-board.py --help` lists the frozen
parent exporter, failed-run input directory, original sources/checkpoint and
new output directory. Run it on RK3588S. The one-graph compiler performs
non-quantized compilation; exporting/tracing and numerical forwards remain
on the board. Preserve the original eight index entry dictionaries exactly.

The public generated/fake source tests can be run from this directory:

  V42_V41_CALLBACK=./v41_online_update.py \
  V42_V41_DRIVER=./run-v41-online-npu-board.py \

  test_v42_eof_compiler.py test_v42_eof_source_export.py \

These 50 checks passed; they do not execute a real model or SDK. Saved-array
and trajectory audits use separately supplied recorded files and no inference.
