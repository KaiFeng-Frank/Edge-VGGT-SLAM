# Fresh-observation DPVO CPU research (v30)

This optional experiment is separate from the default VGGT model and SL4 mapper. It preserves the pinned DPVO learned frontend lifecycle with CPU FP32 execution: the original two CNNs through CPU ONNX Runtime, original Torch Update, native CPU correlation, and the vectorized online BA equations. It adds no ORB, LK or PnP pose frontend. It is not a complete dense SLAM system or an accepted real-time replacement for VGGT.

`dpvo_stream.py` injects model, correlation and geometry executors into an owned NumPy graph. It retains eight-admitted-frame initialization, twelve initialization updates, recurrent hidden states, source-age factor removal, keyframe deletion and relative-pose reconstruction. The first initialization graph has 6,144 edges at the original 96 patches per frame. The earlier E864 ORT Update is not used for this changing graph. Capacities are explicit; failures stop without publishing an old pose. The frame capacity is 64, not the original 4,096-slot buffer. CPU FP32 and CPU RNG do not claim CUDA numerical identity.

`run-v30-dpvo-stream-board.py --help` lists required external artifacts. Execution is guarded to Linux RK3588. Supply the original source/weight artifacts from v26, v26 CPU ORT encoders and three-frame captures, v27 native correlation library/build receipt, and v29 vectorized geometry. Each artifact is hash checked. Use the adjacent `source-freeze.json` with `--source-manifest`, and pass explicit `--stream-module` and `--encoder-module` if moving files. The board environment requires Torch 2.3.1 CPU, NumPy 1.26.4, OpenCV, the measured CPU ORT runtime, four available A76 CPUs and the external TUM fr1_xyz sequence. No model, dataset, vendor binary or compiled library is redistributed.

The research invocation uses `--frames 192 --seed 20261011 --run-time-limit 1200`, first consecutive RGB entries at stride one, and serial unpaced file replay. It preserves the original reader's BGR, undistortion, 608×464 crop, intrinsics and normalization. The first three frames are bound to the original PNG/crop/input bytes and saved encoder outputs. All actual model execution takes place on the board. GT is never supplied to inference.

A software file-admission marker is not a camera exposure timestamp. Fresh poses are recorded only after the current admitted frame's Update/BA succeeds. Waiting/skipped observations and the twelve EOF refinement updates do not count. Before/after-termination arrays are saved separately; model loading, hash/report I/O and EOF work remain visible outside per-frame processing.

The saved-numeric evaluator uses a predeclared one-second endpoint plan from all requested source times, nearest GT association within 20 ms, and one positive Sim3 alignment for each population. Fresh online poses and EOF reconstruction remain separate, with coverage. These short-sequence diagnostics do not establish accuracy versus VGGT, physical-camera latency, dense mapping, 30-minute endurance or 8 GB operation.
