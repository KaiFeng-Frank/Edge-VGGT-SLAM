完整原权重 CameraHead 已在 16 GB RK3588S 上完成独立子网络实验：保留 4 次迭代、16 次 trunk block 调用，输入为原 CPU aggregator 保存的 `[1,2,2048]` camera tokens，输出为 `[1,2,9]` 位姿编码。RKNN 2.3.2 普通模式首调用完整 I/O 耗时 **185.979 ms**，后 3 次平均 **203.646 ms**（4 次平均 199.229 ms）；原 FP32 CPU CameraHead 的 3 次平均为 **1.254 s**。NPU 时间包含输入提交、同步执行、输出取得、复制和释放，排除模型初始化、文件保存和比较；CPU 参考包含少量 trunk hooks。这是一组短时子网络测量，尚未接入完整 VGGT/跟踪/地图流水线，也不能据此声称整网吞吐或 20 Hz 验收通过。

另 4 次实际 SDK profile 均报告 **207 个内部算子在 NPU 上执行、1 个末端 Reshape 在 CPU 上执行**，输入/输出算子也在 CPU 上。因此完整 CameraHead 不能标成“所有内部算子都在 NPU”。原 ONNX 共享 69 个权重张量，但 RKNN 文件仍有 1.711 GB，SDK 报告 DMA 分配 **3,424,231,424 字节（3.424 GB，十进制）**；这不是全机 RSS，也未证明 8 GB 运行。普通与 profile 两组共 8 次实际调用均完成输出释放、context 销毁及亲和性恢复。

相同输入的 8 份 NPU 输出逐元素一致。相对原 FP32 CameraHead 的编码误差为 **relative L2 0.7669%**、最大绝对误差 **0.006504**，固定逐元素 `rtol=1e-4, atol=1e-5` 门限未通过。按官方 XYZW 四元数编码解读，两帧旋转误差为 **0.778° / 0.869°**，平移 L2 误差为 **0.005755 / 0.005816 模型单位**；FoV 高/宽最大绝对误差为 **0.318° / 0.129°**，对应 `fy` 相对误差最大 **2.676%**。这些是子网络与 FP32 参考之间的差异，不是米制误差、GT 精度或累计整网精度。板端 ORT 对原输入和一个预先固定的扰动输入均通过同一逐元素门限，支持导出图的对应性。实际硬件结果及文件/程序 SHA256 收录于配套结果 JSON；权重、RKNN 文件、图像、捕获张量和 SDK 不随仓库发布。
