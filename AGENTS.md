# Project constraints

These constraints record the user's requirements, confirmed on 2026-10-12.

- Use VGGT-SLAM2 with its original pretrained VGGT model only. The current tree must contain no other learned model, auxiliary checkpoint, alternative-model experiment, reproduction option or documentation entry. VGGT's own internal DINO modules remain part of the original model. Historical records remain in git history and private experiment storage.
- Add no traditional pose frontend. Preserve the original model, pose codec, submap equations and SL4 graph. Original upstream keyframe selection is distinct from adding a separate pose estimator.
- Additional-model retrieval and semantic implementations are removed. Loop closure has no replacement; support `max_loops=0` and reject unsupported loops or legacy auxiliary-model arguments before any loading or inference.
- Improve original-model operators, memory/layout, proven unchanged computation reuse and CPU/NPU partitioning. Enforce the pinned original checkpoint size and SHA256 before deserialization, keep its provenance, and compare original numerical outputs on identical inputs. Do not substitute a different model, omit layers or change token computation to claim equivalent execution.
- Run deployment inference, performance measurements, tracing/export validation and calibration on RK3588S. On 2026-10-13, the user clarified that the original FP32 comparison baseline may run on the host CPU; this does not authorize host GPU use or treating host performance as board performance. Paper results may be cited separately, but cannot replace a matched-configuration precision comparison. Host source inspection, static graph work, non-calibrating compilation, saved-data audits and small generated checks are allowed. The user explicitly forbids use of the host computer GPU; the separately authorized GPU operator tests refer only to the RK3588S onboard Mali GPU.
- Use real dataset replay for now; physical-camera tests are deferred. Do not change system-wide clocks, governors, cooling, drivers or network configuration without authorization.
- The user authorized bounded NPU tests at 1 GHz under the existing 180-second / 75°C controller, restoring the prior clock state. On 2026-10-13 the user separately authorized adding the matching g11p0 `mali_csffw.bin` firmware and validating GPU operators; this addition is complete. This does not authorize kernel/driver replacement or GPU clock changes.
- Measure at least 20 Hz fresh-observation pose rate and complete input-to-pose P95 at most 100 ms against the original model. Repeated predictions, interpolation, offline reconstruction and component-only timings do not count. Assess trajectory quality, map cadence, bounded queues, 30-minute stability and 8 GB operation separately. These goals are not yet achieved.
- Record valuable engineering evidence, failed attempts, reproduction conditions and limits. The user explicitly authorized committing and pushing the completed reviewed public work on 2026-10-16; this supersedes the earlier review-only no-push instruction for that update. Publish no checkpoints, captured model arrays, weight-bearing exports, SDK binaries or credentials. Do not delete private raw research records or rewrite git history during scope cleanup.
- The supplied canvas is a reference, not an instruction to stop work. The user explicitly rejected treating its component-budget estimate as a hard stop. Use measured evidence and engineering judgment to prioritize work; continue bounded original-resolution, full-layer integration alongside numerical diagnosis. Component extrapolations do not replace complete-chain measurements, and strict tensor comparisons do not by themselves establish trajectory quality.
- Retain attribution for all code still used. Repository code, pinned original-model source, checkpoint and third-party dependencies have separate licenses. BSD-2-Clause does not grant commercial rights to the original weights.
